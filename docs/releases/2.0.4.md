This update fixes a native-service startup failure reported at church in 2.0.3: “Russian Screen output could not prepare its first frame: The presentation font did not become available.”

- Show now confirms that each presentation font face actually loaded and was registered. A false negative from Chromium's CSS font query no longer prevents the show from starting.
- Output windows validate SyncShow's complete bundled Liberation Sans fallback. Installed Arial remains preferred for presentation layout.
- A small **Save diagnostics…** button appears after a failed Start. It saves a JSON file with app/OS/runtime versions, GPU and display details, output routing, presentation counts, font readability and hashes, and the last startup error. Passwords, authorization tokens, account emails, full file paths, and presentation contents are excluded.

Install this update on the church computer, reopen the intended service, and try Start Show again. If startup still fails, choose **Save diagnostics…** in the error dialog and send the saved JSON file with the screenshot.

Windows native output startup is now rehearsed in the release build, and the installer is installed and launched before publication. The church's physical display setup still needs its own rehearsal after installation.
